# Чеклист безопасности

## Сторона getatom

- [ ] Кука сессии getatom — **host-only** (`getatom.ru`, без `Domain=.getatom.ru`), `Secure; HttpOnly; SameSite=Lax`
- [ ] Приватный ключ подписи — только в секретах деплоя, не в git, не в логах
- [ ] TTL токена 60 секунд, `jti` уникален (UUIDv4)
- [ ] В claims нет email, телефона, внутренних ID, платёжных данных
- [ ] `sub` — псевдонимный UUID из `user_sso_ids`, отдельный на каждый сервис-партнёр
- [ ] `/api/sso/{service}` доступен только с живой сессией; аноним → логин с `returnUrl`
- [ ] Редирект строится только из реестра сервисов (никаких `redirect_uri` из query — исключает open redirect)
- [ ] JWKS отдаёт только публичные ключи; ротация по процедуре из [jwt-spec.md](jwt-spec.md)

## Сторона партнёра

- [ ] Принимается только `alg: RS256`; `none`/HS* отклоняются до проверки подписи
- [ ] Проверяются `iss`, `aud`, `exp`, `iat` (skew ≤ 30с), подпись по `kid` из JWKS
- [ ] `jti` одноразовый: хранилище использованных до `exp + 30с`
- [ ] После обработки — немедленный redirect, токен не остаётся в URL
- [ ] `token` маскируется в access-логах и APM
- [ ] Своя кука сессии: host-only, `Secure; HttpOnly; SameSite=Lax`
- [ ] `/sso` не работает в iframe
- [ ] Нет петли редиректов при невалидном токене (маркер `retry=1`)

## Общее / организационное

- [ ] Данные, создаваемые пользователями внутри сервиса партнёра, покрыты договором (DPA): назначение, экспорт, удаление по требованию, запрет вторичного использования
- [ ] Контакты для инцидентов безопасности обменяны в обе стороны
- [ ] Тестовый прогон: валидный токен, истёкший, повторный `jti`, чужой `aud`, `alg: none`, мусор вместо токена

## Модель угроз — что закрыто

| Угроза | Защита |
|---|---|
| Партнёр читает сессии getatom | Куки host-only, наружу уходит только JWT |
| Перехват ссылки с токеном | TTL 60с + одноразовый `jti` + немедленный redirect |
| Подделка токена партнёром или третьей стороной | RS256, приватный ключ только у getatom |
| Токен для одного сервиса скормлен другому | Строгая проверка `aud` |
| Деанонимизация пользователей партнёром | Псевдонимный `sub`, PII в токене нет |
| Open redirect через issuer | Целевой URL только из реестра сервисов |
