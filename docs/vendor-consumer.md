# Сторона партнёра (consumer) — интеграция

Что нужно реализовать сервису, размещённому на `crm.getatom.ru`, чтобы принимать пользователей getatom. Рабочий пример на Node.js — в [examples/vendor-node/](../examples/vendor-node/).

## Один эндпоинт: `GET /sso?token=<jwt>`

Порядок обработки запроса:

1. **Достать токен** из query-параметра `token`. Нет токена → редирект на `https://getatom.ru/api/sso/crm` (пусть getatom выпустит новый).
2. **Проверить подпись** по JWKS `https://getatom.ru/.well-known/jwks.json`:
   - ключ выбирается по `kid` из header;
   - допустим только алгоритм `RS256` — токены с `none`, `HS256` и прочими **отклонять до проверки подписи**;
   - JWKS кэшировать (~10 минут), при неизвестном `kid` перечитать один раз.
3. **Проверить claims**:
   - `iss === "https://getatom.ru"`;
   - `aud === "crm.getatom.ru"` (ваш хост);
   - `exp` не истёк, `iat` не в будущем — clock skew не более 30 секунд;
   - `jti` ещё не использован (см. ниже).
4. **Погасить `jti`**: сохранить его в хранилище (Redis/БД/память с TTL) до `exp + 30с`. Повторный токен с тем же `jti` → отказ. Это защита от перехвата ссылки.
5. **Find-or-create пользователя** по `sub` (стабильный псевдонимный UUID). `name` — только для отображения, не идентификатор.
6. **Создать свою сессию**: собственная кука со флагами `Secure; HttpOnly; SameSite=Lax`, **host-only** (без `Domain=`) — она не должна утекать на другие поддомены getatom.ru.
7. **Немедленный redirect** на страницу приложения (например `/`), чтобы токен исчез из адресной строки, истории и Referer.

## Обработка ошибок

| Ситуация | Действие |
|---|---|
| Токен истёк / нет токена | `302 → https://getatom.ru/api/sso/crm?retry=1`. Если запрос уже пришёл с `retry=1` и снова невалиден — показать страницу ошибки, **не редиректить** (защита от петли). |
| Невалидная подпись / `iss` / `aud` | `403` + страница ошибки. Не редиректить: это не «протухло», это атака или misconfig. |
| Повторный `jti` | `403`, залогировать инцидент. |

## Что партнёр обязуется НЕ делать

- Не логировать значение токена (в access-логах маскировать query-параметр `token`).
- Не запрашивать и не хранить email/телефон пользователей getatom — их нет в токене by design; идентификатор пользователя — `sub`.
- Не выставлять куки с `Domain=.getatom.ru`.
- Не встраивать `/sso` в iframe (`X-Frame-Options: DENY` на этом маршруте).

## Выход (logout)

Сессии независимые: logout в сервисе партнёра гасит только его куку. Разлогин в getatom не завершает сессию партнёра автоматически (back-channel logout вне рамок v1). Рекомендуемое время жизни сессии партнёра — не больше 24 часов, дальше пользователь просто снова пройдёт бесшовный `/sso`.

## Чеклист готовности к подключению

- [ ] `GET /sso?token=` реализован, все проверки из шага 2–4 включены
- [ ] Редирект после логина убирает токен из URL
- [ ] `jti` replay protection работает (проверяется повторной подачей того же токена)
- [ ] Кука сессии: `Secure; HttpOnly; SameSite=Lax`, host-only
- [ ] `token` маскируется в логах
- [ ] Страница ошибки без редирект-петли
- [ ] Прогнан против [examples/vendor-node/](../examples/vendor-node/) мок-issuer'а или тестового стенда getatom

После этого пришлите нам URL эндпоинта — мы включим сервис в реестр и выдадим финальные `aud`/JWKS.
